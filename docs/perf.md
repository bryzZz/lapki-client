# Производительность холста: как мерить

Здесь описано, как оценить, тормозит ли холст редактора, и как проверить, что оптимизация помогла и ничего не сломала.

Порядок работы всегда один:

1. Зафиксировать сценарий и цель: **p95 времени кадра ≤ 16 мс** (60 FPS).
2. Снять baseline.
3. Найти узкое место по профилю, а не на глаз.
4. Исправить **одно** место.
5. Перемерить и сравнить с baseline. При необходимости повторить.

Результаты каждого шага записываются в [perf-log.md](perf-log.md).

## Инструменты

| Что                   | Где                                                                         | Зачем                                                                   |
| --------------------- | --------------------------------------------------------------------------- | ----------------------------------------------------------------------- |
| Тестовые схемы        | `demos/perf/*.graphml`, генератор `npm run perf:gen`                        | Одинаковые большие документы для всех замеров                           |
| Тест-снимок геометрии | `src/renderer/src/lib/perf/geometry.snapshot.test.ts` (входит в `npm test`) | Страховка: оптимизация не должна поменять размеры, хит-тест и отрисовку |
| Бенчмарк без GUI      | `npm run perf:bench`                                                        | Быстрый воспроизводимый замер JS-части (без растеризации)               |
| FPS-оверлей           | `Ctrl+Shift+F` в приложении                                                 | Посмотреть FPS руками                                                   |
| Прогон в приложении   | `copy(await __perf.run())` в консоли DevTools                               | Те же сценарии, но в настоящем Electron с настоящей отрисовкой          |

### Тестовые схемы

| Файл                         | Состояний | Переходов | Глубина вложенности |
| ---------------------------- | --------- | --------- | ------------------- |
| `perf-flat-200.graphml`      | 200       | 300       | 1                   |
| `perf-medium-depth3.graphml` | 104       | 156       | 3                   |
| `perf-deep-depth6.graphml`   | 63        | 95        | 6                   |
| `perf-large-depth4.graphml`  | 320       | 480       | 4                   |

Файлы детерминированные, `npm run perf:gen` всегда даёт одно и то же. Параметры задаются в `scripts/perf/gen-perf-demos.ts`.

### Сценарии

Они общие для бенчмарка и прогона в приложении (`src/renderer/src/lib/perf/scenarios.ts`). Ввод подаётся через те же обработчики, что и от настоящей мыши.

| Сценарий          | Что делает                                                                     |
| ----------------- | ------------------------------------------------------------------------------ |
| `frame`           | Перерисовка кадра без изменений                                                |
| `pan`             | Панорамирование правой кнопкой                                                 |
| `zoom`            | Смена масштаба                                                                 |
| `hover`           | Движение мыши без кнопок (хит-тест под курсором)                               |
| `drag-nested`     | Перетаскивание самого глубоко вложенного состояния                             |
| `drag-parent`     | Перетаскивание корневого состояния с самым большим поддеревом                  |
| `frame-fit`       | То же, что `frame`, но камера «вся схема в кадре» (или максимальное отдаление) |
| `pan-fit`         | Панорамирование, видна вся схема                                               |
| `drag-nested-fit` | Перетаскивание самого вложенного состояния, видна вся схема                    |
| `drag-parent-fit` | Перетаскивание корневого состояния с самым большим поддеревом, видна вся схема |

## Что сделать для проверки (WSL)

1. Переключиться на ветку и запустить приложение в режиме разработки:

   ```sh
   git checkout perf/canvas
   npm install
   npm run dev
   ```

2. Открыть схему: **Файл → Открыть** (`Ctrl+O`) → `demos/perf/perf-large-depth4.graphml`. Перейти на вкладку с машиной состояний.

3. Нажать `Ctrl+Shift+F`, справа сверху появится плашка с FPS. Поводить, потаскать состояния, позумить. Это нужно для ощущений, цифры брать из следующего шага.

4. В DevTools (в dev-режиме они открыты сразу, иначе `Ctrl+Shift+F12`) на вкладке **Console** выполнить:

   ```js
   copy(await __perf.run());
   ```

   Прогон длится около 15 секунд. Мышью в это время холст не трогать. В конце в консоли появится таблица, а `copy()` (встроенная функция консоли DevTools) положит в буфер обмена текстовый отчёт: блок от строки `Холст …` до строки `кадр — интервал …`. Если буфер не сработал, скопировать этот блок из консоли руками. Массив из `console.table` копировать не нужно.

   Перед замерами лучше выключить автосохранение (**Настройки → Автосохранение**): иначе приложение перезапишет файл схемы, а сценарии перетаскивания сдвигают состояния. Если файл всё же изменился, вернуть его: `git checkout demos/perf`.

5. Повторить шаги 2–4 для каждого файла из `demos/perf/` и прислать все отчёты (вставить в чат или в описание PR).

6. Отдельно на `perf-large-depth4.graphml`: открыть панель **симулятора** и снова выполнить `copy(await __perf.run())`. Так видно, влияет ли открытый симулятор.

Сценарии без `-fit` начинают с камеры, как при открытии схемы (масштаб 1, видна часть схемы). Сценарии `-fit` отдаляют камеру так, чтобы была видна вся схема. Разница между ними — это стоимость растеризации того, что видно на экране: в бенчмарке без GUI её нет, поэтому `-fit` там стоят столько же.

Можно гонять отдельные сценарии: `await __perf.run({ scenarios: ['drag-nested', 'pan'] })`. Список сценариев лежит в `__perf.scenarios`.

### Как читать таблицу

- **FPS, кадр p50/p95/max** — интервал между кадрами браузера, то есть всё вместе: наш JS, растеризация canvas, React. Цель: p95 не больше 16–17 мс.
- **отрисовка p50/p95/max** — сколько занял `view.draw` холста, только наш код отрисовки.
- Если «кадр» сильно больше «отрисовки», время уходит не в холст: в растеризацию, React, симулятор.

### Про WSL

В WSL графика может работать через программный рендеринг, поэтому абсолютные цифры будут хуже, чем на Windows. Для сравнения «до/после» это не важно: смотрим, **во сколько раз** стало лучше. Итоговая проверка проводится один раз в Windows-сборке: `__perf` и `Ctrl+Shift+F` есть и там, DevTools открываются по `Ctrl+Shift+F12`.

## Профиль в DevTools, если нужно копнуть глубже

1. DevTools → вкладка **Performance** → кнопка записи (●).
2. 3–5 секунд потаскать состояние на большой схеме (или выполнить `__perf.run({ scenarios: ['drag-nested'] })`).
3. Остановить запись. Внизу открыть вкладку **Bottom-Up** и отсортировать по **Self Time**.
4. Сверху окажутся самые дорогие функции. Сохранить профиль (↓ Save profile) и прислать файл `.json`.

## Бенчмарк без GUI

```sh
npm run perf:bench
```

Он гоняет все сценарии на всех схемах из `demos/perf` в jsdom. Канвас там подменён заглушкой, поэтому цифры показывают стоимость только нашего JS (обход дерева, геометрия, хит-тест), без растеризации. Результаты печатаются таблицей и сохраняются в `perf-results/bench-latest.{md,json}` (папка в `.gitignore`). Кроме времени, выводятся:

- число вызовов геометрии `Shape` (`computedWidth`, `childrenContainerHeight`, `getIntersection`) на шаг;
- число вызовов `getColor` на шаг (каждый из них в приложении — это `getComputedStyle`);
- CPU-профиль по собственному времени функций для сценариев `frame`, `hover` и `drag-nested`.

Фильтры: `PERF_DOCS=deep,large PERF_SCENARIOS=drag-nested PERF_PROFILE=0 npm run perf:bench`.

## Проверка, что ничего не сломалось

Автоматически: `npx vitest run src/renderer/src/lib/perf`. Тест-снимок сравнивает для каждой схемы из `demos/` и трёх положений камеры:

- `drawBounds` каждой фигуры;
- результат хит-теста по сетке 48×27 точек экрана;
- хеш всех вызовов отрисовки.

Если оптимизация законно меняет отрисовку (например, перестаёт рисовать объекты за пределами экрана), хеш поменяется. Тогда снимок обновляется осознанно: `npx vitest run -u src/renderer/src/lib/perf`, и в diff снимка должны меняться только `drawHash`/`drawCalls`.

Вручную, на `demos/perf/perf-medium-depth3.graphml` и любой своей схеме с вложенностью:

- [ ] перетащить вложенное состояние внутри родителя: родитель растягивается вправо и вниз, как раньше;
- [ ] вытащить состояние из родителя и вложить обратно (подсветка родителя при наведении работает);
- [ ] перетащить родителя: дети и переходы едут вместе с ним;
- [ ] зум колёсиком с Ctrl и кнопками: всё масштабируется без «прыжков»;
- [ ] клик и двойной клик по вложенному состоянию, по переходу, по событию внутри состояния выделяют нужный объект;
- [ ] подсказки: навести мышь на псевдосостояние (начальное, конечное, выбор, локальная история) и подержать ~0.5 с — появится подпись, например «Начальное псевдосостояние». У обычных состояний и переходов подсказок нет;
- [ ] отмена/повтор (`Ctrl+Z`/`Ctrl+Y`) после перетаскиваний.
